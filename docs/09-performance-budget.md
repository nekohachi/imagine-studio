# 09. 性能予算

「なるべく軽く」を数値にしたもの。フェーズ 0 で両端末の実測値を取り、以降はアプリ内のベンチ画面(macbeth の `bench.ts` と同じ考え方)で手動確認する。CI では取れない。

## 目標

| 項目 | MovinkPad Pro 14 | iPad mini |
|---|---|---|
| ペン先から画面までの遅延 | 16ms 以下 | 25ms 以下 |
| 描画中のフレーム時間 | 8ms 以下(120Hz) | 16ms 以下(60Hz) |
| B4 600dpi モノクロ、20 レイヤー | 快適 | 操作可能 |
| A4 350dpi カラー、30 レイヤー | 快適 | 快適 |
| 起動から描き始めまで(2 回目以降) | 2 秒以内 | 2 秒以内 |
| 核のバンドル | 1MB 以下(JS)、WASM 込みで 2MB 以下 | 同じ |
| アイドル時の CPU | rAF 停止、0% 近辺 | 同じ |
| メモリ上限(タイルの LRU しきい値) | 2GB | 600MB |

## 守り方

| 原則 | 計測 |
|---|---|
| 毎フレーム合成は 3 枚 | 合成の描画呼び出し数をベンチで表示 |
| 汚れた矩形だけ描く | ストローク中の再合成タイル数を表示 |
| ミップで縮小表示 | 全体表示時のフレーム時間 |
| rAF を止める | 無操作 1 秒後の CPU |
| 核だけ読む | Vite のバンドル解析、動的 import の境界をテストで固定 |
| RGBA8 / R8 のみ | シェーダのテクスチャ型を lint |
| ダブ数の上限 | 1 ストロークのダブ数と間隔の自動補正を表示 |
| フレームごとに 1 回描く | ポインタイベント数と描画回数の比 |

## 端末固有

- Safari: メモリ超過は黙って再読込になる。LRU しきい値を保守的にし、超えそうなときは HUD に警告を出す。
- Safari: `getPredictedEvents` と `desynchronized` は無い前提で、遅延目標を別に置く。
- Chrome: `pointerrawupdate` を購読すると入力の間引きが減る。遅延計測はこれを含めて行う。
- 120Hz: rAF が 120 回来るので、合成を 8ms に収める。収まらないときは描画を 60Hz に落とす(入力は 120Hz のまま受ける)。

## 計測方法(フェーズ 0)

1. 遅延: 高速度カメラ(端末のスローモーション動画)でペン先と線の先端の距離を測り、ペンの移動速度で割る。
2. フレーム時間: `performance.now()` の差分をベンチ画面に表示。
3. メモリ: `performance.memory`(Chrome)と、Safari は再読込が起きるまで原稿サイズを上げる。
4. 起動: Service Worker のキャッシュ後にリロードして計測。
